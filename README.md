# Ginti · गिनती

Maths practice you do by talking. The app reads a sum aloud, the child says the answer in Hindi or English, and the app says whether it was right. No typing, no reading a paragraph of instructions, no account.

It is built for children who can say the answer long before they can type it, and for any classroom where the one working device is a cheap phone.

```
docker compose up
```

Then open http://localhost:8000. That is the whole setup. There are no API keys, no `.env` file is needed, and nothing is sent to any outside service.

## What it does

- **Say the answer.** Tap the microphone, say "पचपन" or "fifty five". The app shows what it heard for two and a half seconds so the child can say "नहीं, फिर से बोलो" before it counts.
- **Hindi or English.** Hindi numbers 1 to 99 are 99 different words with no pattern ("उनहत्तर", "अट्ठासी"), so they are written out in full and checked, not generated by a rule.
- **Adaptive.** Addition, subtraction and times tables, four levels each. A fact answered wrong comes back soon; one answered right comes back later. Five right in a row moves up a level, three misses in a row move down.
- **Spoken commands.** "दोबारा" / "repeat" hears the question again. "छोड़ो" / "skip" moves on.
- **Teacher view** at `/teacher`: for each learner, recent accuracy, median time on right answers, level per topic, and the facts they keep missing (for example "7x8, missed 3 of 4"). CSV export, and a delete button per learner.
- **Typing still works** for a child who is somewhere noisy.

## How it works

1. The browser captures the microphone, turns it into 16 kHz mono audio and streams it over a WebSocket.
2. The server decodes it with [Vosk](https://alphacephei.com/vosk/), an open-source offline speech recogniser, using its small Hindi and Indian-English models.
3. For each question the recogniser is **limited to the words needed to say a plausible answer**, plus the two commands. For "3 + 4" it can only hear numbers up to 20, so "सात" cannot turn into "साठ" (60). This is what lets a small model do well on short answers.
4. What it heard goes through a number parser (Devanagari, Roman Hindi, English words, digits). Anything that is not a clean number, like "seven eight", is treated as not heard. The app never guesses.
5. The server holds the correct answer. The browser never receives it.

Audio is kept in memory for one answer and then dropped. The database holds a nickname, answers and timings, nothing else.

## How well does it hear? (measured, and what that does not tell you)

`scripts/bench_asr.py` over 508 clips made with neural text-to-speech voices (two voices per language), numbers 0 to 99 plus every 37th number from 100 to 999, plus the commands:

| | 0 to 99 | 100 to 999 | commands |
|---|---|---|---|
| Hindi | 200 / 200 | 46 / 50 (92%) | 4 / 4 |
| English | 198 / 200 | 50 / 50 | 4 / 4 |

All together: 502 of 508 (98.8%). Decoding ran at about 66 times faster than real time on one CPU core (1,012 seconds of audio in 15 seconds).

Read this carefully:

- These voices are **synthetic**. They are clean, even and adult. This says nothing yet about real children, real classrooms, phone microphones or noise. It shows the number tables, the grammar limit and the audio path work. Nothing here has been tested with a child.
- Hindi hundreds are the weak spot. The recogniser sometimes drops "सौ" ("पाँच सौ चौवालीस" heard as "पाँच चौवालीस"), and "सात" and "साठ" can still swap when the range is wide.
- Without the answer-range limit, plain free-form recognition got 90 of 100 on Hindi 0 to 99 in a first test (the other 10 were spelling variants or similar sounds). The limit is what closes that gap.

## Limits you should know about

- Chrome and Edge need `localhost` or HTTPS for the microphone. On a school network that means putting a TLS proxy in front. See [SECURITY.md](SECURITY.md).
- Reading the question aloud uses the device's own text-to-speech voice. If a phone has no Hindi voice, the question is only on the screen. This has been tried in one browser only.
- No real accounts. A nickname is the login, so anyone can practise as someone else's nickname. The teacher page has a PIN.
- Answers are whole numbers up to 9,999. Addition, subtraction and multiplication only. No division, fractions or word problems.
- One server process, at most eight microphone sessions at a time, SQLite on a Docker volume, no backup.
- The audio can be wrong. A child can be marked wrong because the app misheard. That is why the heard number is shown first and the redo button exists.

## Run the tests

```
pip install -r requirements-dev.txt
python scripts/fetch_models.py models
GINTI_MODEL_DIR=models python -m pytest -q tests
```

78 tests: number round trips for 0 to 9,999 in both languages, the question engine, the database, every API route including bad input and the PIN lockout, and recognition of recorded fixtures. Tests that need the speech models skip themselves if the models are missing.

`scripts/e2e_browser.py` drives the real page in Chrome and plays prerecorded clips into its microphone path, so the whole chain (stream, worklet, WebSocket, recogniser, scoring, feedback) is exercised. In a run of one 10-question round with synthetic English clips all 10 were scored right. Those clips are recorded, not live speech.

CI builds the image with `docker compose up`, waits for it to be healthy and runs `scripts/smoke.py` against it.

## Layout

```
app/numbers.py   Hindi, Roman Hindi and English numbers in both directions
app/speech.py    Vosk wrapper, per-question grammar, spoken commands
app/engine.py    question choice, difficulty, spaced repetition
app/store.py     SQLite: learners, attempts, boxes, levels
app/main.py      HTTP API, WebSocket, security headers, teacher routes
app/static/      the pages (plain HTML, CSS and JavaScript, no build step)
scripts/         model download, test-audio maker, benchmark, smoke test, browser run
```
